# 生成质量评测

质量回归集覆盖 12 种模板 × 中文/英文，共 24 条人工编写的合成资料，以及数字替换、否定反转、无关断言三个故障注入。它检查结构、语言、模板合同、时间线及审阅提示，不是事实准确率或人工成片评分。

```bash
pnpm eval:quality
```

报告默认保存为仓库根目录 `quality-report.json`（Git 忽略），也可用 `GLINT_QUALITY_OUT` 指定路径。数据集在 `examples/evaluation/cases.json`，可直接补充新的回归案例。2026-10-21 离线模式 24/24 合同、3/3 故障提示通过。

## 真实模型

设置服务端 `GLINT_LLM_*` 后，令 `GLINT_EVAL_LIVE=1` 再运行同一命令。它会实际调用配置的模型，并可能计费；不会用离线引擎冒充模型结果。没有 Key 时明确失败。

模型编排遇到 JSON、schema 或模板错误时，最多追加一次修复请求；传输错误不自动重试。可通过 `composeWithLlm` 的 `repairAttempts: 0..2` 控制，默认 1；支持 AbortSignal。超过 12000 字的资料明确拒绝，要求拆分，不再静默截断后半段。

## 人工验收

每条成片按下列四项各打 1–5 分，并留下具体场景和修改意见：事实与资料一致、讲解结构、画面/字幕可读性、配音自然度。先隐藏模型名，再评分，最后揭晓。比较模型时固定资料、模板、参数与评分人员，并保留失败样本。

旁白依据界面显示原文候选及数字/否定/重复提示；编辑后需要重新核对。词汇匹配无法证明事实正确，也不能验证模型自己扩写的资料。建议真实用户集至少 20 条资料，再决定是否发布。

配音相似度、发音、自然度和停顿可在工作台的「配音听评」里评分，导出带日期和 A/B 对照的 JSON。文件仅在浏览器播放，不上传；评分由听者填写，未评分不会自动填入分数。

## 自动模型回归

GLM-5.3-Flash 已完成 24/24 模板合同与 3/3 故障提示回归。`scripts/evaluate-grounding.mjs` 可在指定的报告上检查资料一致性，保存发现、原项目、一次修复与复查结果。该组资料发现的 4 项问题重新生成后通过同模型复查；这不是独立标注集的事实准确率。

运行前配置 `GLINT_QUALITY_OUT` 指向 `eval:quality` 的报告，以及服务端模型变量。逐案例正文、模型回复和诊断存放在报告旁的 `.cases/` 目录，默认被 Git 忽略。人工盲测仍未执行，Qwen 同模型 embedding cosine 不作为人评替代。
