# 工作流详解:十步、三模式与确认门

流程骨架(三方案→确认→逐镜→QA)吸收自 xilo-opus-video / video-shotcraft / huashu-art-motion 的公开方法论,做法见 `attribution.md`;门禁数值以本仓库实测为准。

## §1 输入处理

- **资料**:先提炼事实提纲(核心信息/受众/必须出现的数字),事实只能来自资料;不确定的不写。长资料按问题定位片段,不整篇重读。
- **口播音频**:有稿走 `--tts` 正常管线;无稿先转录(knowledge 的 media adapters,或用户自备稿)。口播驱动的分镜:镜头跟句子切,一镜 1.5–5s,一镜只讲一件事。
- **想法**:追问会改变方案的 ≤3 个问题(时长/画幅/是否配音/品牌色或风格);没说的用默认(30s、16:9、配音、风格三选一)并在方案里写明。
- **BGM 卡点**:用户指定音乐时先 `pnpm glint beats --audio=x --out=beats.json`;返回的是启发式网格,把分镜切点对齐到返回的 beatsMs 后,渲完用 qa 复核。不编造没测过的 BPM。

## §2 风格三选一(确认门①)

给 **2–3 个方案**,差异必须在画风或叙事结构上(一个稳妥贴资料、一个风格化、一个结构大胆),不许只换配色。每个方案给:风格包名、一句话画面概括、叙事结构、预计时长。用户已点名风格(「用手绘笔记风」)→ 视为已选定,直接执行。

## §3 分镜与 lint(确认门②)

镜头表给用户看:每镜 `时间段 | 画面(具体的物+动作) | 旁白 | 运镜/转场`。lint 红灯必修:`consecutive-push`(连续三镜推近)、`card-ending`(字卡结尾)是常见病;黄灯六种(空镜/超长镜/重复转场/蓝紫底/图表无标题/列表占比>60%)逐条给理由或修掉。

## §4 渲染矩阵

| 场景 | 命令要点 |
|---|---|
| 日常出片 | `--tts=auto`(edge 优先,离线回落 sapi/mock)| 
| 快速草稿 | `--fast`(半尺寸 veryfast);确认后再出 `--encoding=balanced|quality` |
| 改单镜验证 | `--scenes=<id>`(其他镜不重渲;时长按旁白独立,拼接仍对齐) |
| 回剪映 | `--plate` 出无字幕/无音乐/无 SFX 底片,字幕用 srt 或剪映文本轨 |
| 无网关配乐 | `--music=synth [--music-mood=calm|warm|bright] [--music-seed=N]`(确定性,同种子同字节) |
| 静音测试 | `--tts=mock`(无声,不是配音成片) |

## §5 QA 闭环

`pnpm glint qa --video=成片 --strict`:红灯修完重渲(只重渲有问题的 `--scenes`),黄灯写理由;报告 `--out=` 存档进交付。阈值与修法见 `references/qa-gates.md`。确定性与布局回归另有 `pnpm verify:render` / `verify:layout`。

## §6 排练(独有,可选)

LLM 配置存在时:`make --rehearse`(虚拟听众试讲,报告困惑点)→ `--polish`(自动重讲前 2 个困惑点)。无 key 时跳过并说明,不假装排练过。

## §7 交付契约

成片 MP4、project JSON、SRT、QA 报告、(可选)剪映草稿目录、(可选)排练报告。注明:实测过的命令与输出;未验证项(如剪映未真机验证);自主模式下替代确认的关键判断清单。
